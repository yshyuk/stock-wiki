## 1. 미해결 — 동시호가 배분 우선순위 (1-3·1-4·2-6 모두 헤지 유지 중)

동시호가(상·하한가 단일가매매) 상황에서 물량을 나누는 내부 순서 — 위탁매매우선이 수량우선에 앞서는지 — 를 1차 출처로 확정하지 못했어요.

- 유가증권시장 업무규정 시행세칙 제34조 원문을 여러 차례 확보 시도했으나 실패했습니다.
- 법제처 easylaw는 위탁자우선을 ETF·ETN·ELW로 한정해 서술합니다.
- KRX regulation 페이지는 위탁매매우선을 언급하지 않고 "매매수량단위 100배 → 잔량 1/2 → 잔량" 단계별 정량배분만 명시합니다.
- 2차 출처(금투협 등)는 위탁매매우선이 수량우선에 앞서는지를 놓고 서로 갈립니다.

**파트 2 완료 시점 기준으로도 여전히 미해결이에요.** 2-6(상한가·하한가·서킷브레이커)도 내부 순서를 단정하지 않고 1-3·1-4와 같은 수위로 헤지한 채 마무리했습니다("접수 시간의 앞뒤를 따지지 않고 다른 기준으로 물량을 나눠줘요" 정도로만 서술). **1-3·1-4·2-6 세 챕터 모두 이 헤지를 유지하고 있고, 이후 어떤 챕터에서도 이 순서를 단정하지 마세요.** KRX 규정집 PDF나 유료 법령 DB 등 공개 웹 밖 경로로 원문을 먼저 확보하기 전까지는 확정하면 안 됩니다.

### 검색 재현율 — 파트 3 반영 재측정 완료 (2026-08-06)

이전 측정(사이트 구축 프로젝트, 챕터 13개)에서 미뤄둔 판단을 챕터 19개 기준으로 다시 했어요.
측정 스크립트는 `npm run measure:search`이고, `tests/helpers/search-index.js`가 실제 사이트와
같은 `searchOptions`(`fuzzy: 0.2`, `prefix: true`, `boost: title 4 / text 2 / titles 1`)를 씁니다.

**판단: 접미사 색인은 계속 보류. 파트 3 측정에서 보류할 이유가 오히려 하나 더 늘었어요.**

관측 결과는 이래요.

- **`거래소` 손실은 남아 있고 상대적으로 더 나빠졌어요.** 19개 문서 중 18개가 걸리는데 정작
  한국거래소를 다루는 2-1(코스피 코스닥 차이)이 **17위**예요. 파트 3 챕터들이 "거래소"를 자주
  언급하면서 2-1을 더 밀어냈습니다.
- **새로 발견된 문제 — `나스닥`이 코스닥 챕터를 끌어와요.** `나스닥`으로 검색하면 10건이
  걸리는데 2위·3위가 2-2(코스피 지수)와 2-1(코스피 코스닥)이에요. 원인은 접미사 색인이 아니라
  **`fuzzy: 0.2`** 입니다. 세 글자 질의에서 편집거리 1까지 허용돼 `나스닥`이 `코스닥`에 매칭돼요.
  VitePress 로컬 검색의 기본값이라 파트 3 이전에는 드러나지 않았을 뿐이에요 — 코퍼스에 한 글자만
  다른 별개 용어 쌍이 처음 들어왔기 때문에 이제 보이는 거예요.
- **파트 3 대표 질의는 대체로 정상이에요.** `양도소득세`→3-3 1위, `환율`→3-4 1위, `환헤지`→3-4
  1위, `서머타임`→3-2 1위, `미국주식`→3-1 1위, `프리마켓`→3-2 1위. 조사 부착 검색도 여전히 정상.
- **`증자`는 2-5가 1위에서 2위로 밀렸어요**(1위는 2-2). 문서 수가 늘며 점수 정규화가 바뀐 결과로
  보이고, 손실이라 부를 정도는 아니에요.

**보류 근거가 강해진 이유:** 접미사 색인은 부분 문자열 매칭을 늘리는 방향이라 `거래소`는
개선되지만 **`나스닥`↔`코스닥` 유형의 오탐은 오히려 악화**시킵니다. 게다가 색인 크기를 3~5배
늘려 초기 로딩(광고 수익 직결) 비용을 지우고요. **`거래소` 한 건을 고치려다 새로 드러난 오탐을

### 세율 22%의 출처 — 최종 리뷰에서 승격 완료

세율 22%는 "양도소득세 20% + 지방소득세 2%"로 서술했는데, 집필 시점에는 "22%"가 통째로 적힌 1차 출처에 도달하지 못하고 계산으로 도출했어요. **최종 리뷰의 사실검증에서 아래 조합으로 원문 확인이 끝났습니다.**

- 국세청 발간 「해외주식과 세금」 p.11 — 주식 양도소득세율 20%
- 지방세법 제103조의3 (시행 2026-01-01) — 지방소득세는 양도소득세액의 10%

**더 이상 승격 대상이 아니에요.** 다만 세율 20%에는 예외가 있어요 — 해외 상장된 중소 내국법인 주식은 10%, 해외 부동산주식은 누진 6~45%. 초보 범위 밖이라 3-3 본문은 "일반적인 미국 주식의 세율은"으로 한정만 해뒀습니다.

### 파트 4 최종 리뷰에서 잡힌 함정 두 개 (다음에도 똑같이 밟기 쉬워요)

**1. 낡은 출처가 "현행"으로 둔갑했어요.** 4-5 초안이 ISA 납입한도를 "이월되지 않아요"로 썼는데, 그 근거가 위에서 경고한 바로 그 2016년 금융위 페이지였습니다. **현행법은 이월이 가능**하고, "이월 폐지"는 오히려 2026년 개편안이 새로 넣으려는 내용이에요. 즉 **낡은 출처를 믿은 결과가 우연히 미시행 개편안과 같아지면서, 본문에 미시행 제도가 시행 중인 것처럼 들어갔습니다.** handoffs에 "이 페이지는 낡았다"고 적어둔 사람이 같은 프로젝트에서 그 함정에 빠졌다는 점을 기억하세요.

**검증 요령:** 개편안이 어떤 제도를 "폐지·축소한다"고 하면, **그 제도는 지금 존재한다**는 뜻이에요. 개편안 보도를 역방향으로 읽으면 현행 제도를 확인할 수 있어요.

**2. "가능하다"와 "유리하다"를 뒤집어 썼어요.** 4-4 초안이 연금저축을 "중도인출 어려움", IRP를 "법정 사유에 한해 가능"으로 적어 **IRP가 더 유연한 것처럼** 읽혔는데 실제는 반대입니다. **연금저축은 사유 제한 없이 언제든 인출 가능하고(세금 16.5%가 걸림돌), IRP는 법정 사유가 아니면 부분 인출 자체가 막혀 전액 해지밖에 없어요.** "인출 가능 여부"와 "인출 시 세율"은 별개 축인데 이걸 한 칸에 뭉뚱그리면 방향이 뒤집힙니다.

**둘 다 비교표에서 발생했어요.** 표는 한 칸에 한 축만 담아야 하고, 축이 둘이면 행을 나누세요.

설계는 `docs/superpowers/specs/2026-07-30-stock-wiki-site-design.md`,
구현 계획과 검증 결과는 `docs/superpowers/plans/2026-07-31-stock-wiki-site.md`에 있어요.

### 해결된 숙제

- **mermaid 다이어그램 4건의 문법·렌더 확인 완료 (2026-08-04).** 1-1, 1-2, 2-4, 2-7의 다이어그램
  소스를 한 글자도 바꾸지 않고 그대로 옮긴 페이지를 만들어 사이트 소유자가 브라우저에서 직접
  확인했어요. **네 개 모두 그림으로 정상 렌더되고 한글 라벨도 깨지지 않아요.** 1-1의 화살표
  라벨(주식 발행·투자금·배당·매매대금)도 제자리에 붙습니다. 빌드 파이프라인도 함께 확인했어요 —
  mermaid 코드 블록이 플러그인 마운트 지점으로 정상 치환되고(raw 코드 블록 0건, 마운트 1건씩),
  네 소스 모두 mermaid 파서의 정점 생성 단계까지 도달해요.

  **그동안 「정적 문법 검사만 거쳤고 실제 렌더는 아무도 확인하지 못했다」던 상태는 이것으로
  끝났어요.**
- **사이트 전반의 시각 확인도 완료 (2026-08-05).** 배포된 사이트에서 mermaid 다크 모드 연동,
  3단 레이아웃, 375px 모바일 폭에서의 표시를 사이트 소유자가 직접 확인했고 전부 이상 없어요.
  이 프로젝트에서 시각 확인이 필요한 항목은 더 이상 남아 있지 않습니다.

### 집필할 때 알아야 할 것

- **마크다운은 그대로 두면 돼요.** 사이트가 빌드 시점에 변형을 처리해요. 미집필 챕터를 가리키는
  링크를 미리 써 둬도 「집필 예정」 표시로 렌더되고, 그 챕터를 쓰면 자동으로 링크가 살아나요.
  **단, 그 링크는 반드시 상대경로이고 `.md`로 끝나야 해요** (예: `../part3-us-overseas/3-2-us-trading-hours.md`).
  `about/*.md`나 `index.md`에 쓰인 `/about/disclaimer` 같은 절대경로·확장자 없는 스타일을
  아직 쓰지 않은 챕터 링크에 그대로 갖다 쓰면 안 됩니다 — 그 스타일은 `plannedLinks`가
  「집필 예정」으로 인식하지 못해서 `ignoreDeadLinks: false` 설정 때문에 **빌드가 죽어요**.
  (증상: `npm run build`가 해당 링크를 가리키며 dead link 오류로 실패 — 오타처럼 보이지만
  실제로는 링크 스타일 문제일 수 있어요.)
- **`##` 섹션이 4개 이상이면 3번째 섹션 앞에 광고가 들어가요.** 섹션 구성을 짤 때 참고하세요.
  (이 삽입은 `frontmatter.part`와 `order`가 둘 다 숫자인 챕터 페이지에만 적용돼요 — 정책
  페이지나 `order`가 빠진 페이지는 대상이 아니에요.)
- **frontmatter의 `keywords`가 검색 색인에 들어가요.** 그동안은 쓰이지 않았는데 이제 실제
  검색어로 동작하니, 독자가 칠 법한 표현을 넣어 주세요.
- **`description`은 검색 결과와 SNS 미리보기에 그대로 노출돼요.** 이미 그렇게 쓰고 있지만,
  앞으로도 문장으로 완결되게 써 주세요.
- **`date`는 구조화 데이터의 `datePublished`가 돼요.**
- **`part`·`order`는 frontmatter 필수예요 — 이 둘이 SEO 전체를 켜는 스위치입니다.** 둘 다
  숫자여야 그 페이지가 "챕터"로 인식되고, 그래야 `og:type=article`·`article:published_time`·
  JSON-LD(Article + BreadcrumbList)가 붙고 본문 중간 광고도 그 판정을 따라가요.
  **둘 중 하나라도 빠지면 빌드가 에러 없이 조용히 통과하면서 그 챕터는 `og:type=website`로,
  `article:published_time` 없이, JSON-LD 자체가 아예 없이 나가요.** 사이드바에도 안 나오니
  chapters.js와 파일명이 일치하는지도 같이 확인하세요.
  `title`은 필수는 아니고 권장이에요 — 빠지면 VitePress가 문서의 첫 `#` 제목으로,
  그것도 없으면 사이트 이름으로 자동 대체하기 때문에 JSON-LD의 `headline`이나 breadcrumb가
  비는 일은 없어요. 그래도 frontmatter `title`을 명시적으로 채우는 걸 권해요 — `<title>`
  태그·`og:title`·JSON-LD `headline`에 그대로 쓰이는 값이라, frontmatter로 직접 정하는 쪽이
  자동 추출보다 정확하게 통제돼요.
- 챕터를 새로 쓰면 `.vitepress/lib/chapters.js`의 목차 데이터와 파일명이 일치하는지 확인하세요.
  불일치하면 사이드바에 안 나오거나 빈 항목이 생겨요.

### 남은 사항

- **애드센스 미신청.** 광고 슬롯과 정책 페이지는 준비됐지만, `.vitepress/lib/site.js`의
  `ADSENSE_CLIENT`와 `public/ads.txt`에 발행자 ID를 채우는 것만으로는 광고가 게재되지
  않아요. 추가로 필요한 것:
  - **슬롯별 ad-unit ID(`data-ad-slot`)가 없어요.** `AdSlot.vue`는 발행자 ID(`data-ad-client`)만
    넣고 있고 광고 단위 ID는 아예 비어 있어요. AdSense는 이 값 없이는 게재를 시작하지 않으니,
    계정을 만들고 top/mid/bottom 슬롯마다 ad-unit을 발급받아 `AdSlot.vue`에 넣어야 해요.
  - **top/bottom 슬롯이 SPA 네비게이션에서 리필되지 않아요.** 이 두 슬롯이 마운트되는
    컴포넌트는 클라이언트 사이드 라우팅 시 재생성되지 않아서, 첫 하드 로드 이후 페이지를
    이동하면 광고가 다시 채워지지 않아요. mid 슬롯은 페이지 컴포넌트 안에 있어 이 문제가
    없고요 — 셋이 서로 다르게 동작한다는 뜻이니 켜기 전에 라우트 변경 감지 로직을 추가하세요.
  - 두 이슈 모두 `AdSlot.vue` 상단 주석에 자세히 적어 뒀어요. AdSense 계정이 없어 실제
    슬롯 ID도 리필 동작도 테스트할 수 없었던 게 지금 단계에서 구현하지 않은 이유예요.
- **`digestive-coffee.blog`에 다른 콘텐츠가 있는지 확인 필요.** 애드센스가 상위 도메인 단위로
  심사할 가능성이 있어요.
- **`images/` 폴더 7개는 여전히 비어 있어요.** 첫 이미지가 규약(파일명·대체 텍스트·저장 경로)의
  첫 시험대가 돼요.
- **검색의 합성어 내부 일치 손실 — 재측정 보류 중.** 조사 부착 검색은 잘 되지만 `거래소`처럼
  단어 내부에 다른 단어가 들어있는 합성어는 놓칩니다. 상세 수치는 위 3장의
  「검색 재현율 — 합성어 내부 일치 측정」 참고. 챕터가 늘어난 뒤 재측정해서 접미사 색인 도입
  여부를 다시 판단하세요.
