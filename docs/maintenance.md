# 정기 점검 고려사항 (내부 문서)

> **이 문서는 사이트에 표시되지 않아요.** `.vitepress/config.js`의 `srcExclude`가 `docs/**`를 제외하고 있어요. 독자용이 아니라 관리용 메모예요.

## 이 문서를 쓰는 이유

이 위키의 챕터에는 **시간이 지나면 조용히 틀린 글이 되는 문장**이 섞여 있어요. 세율처럼 법이 바뀌면 달라지는 값, "아직 시행 전이에요" 같은 시점 의존 문장, 매년 바뀌는 휴장일 같은 것들이에요. 빌드도 통과하고 테스트도 통과하지만 내용만 낡습니다. **아무도 알려주지 않으니 이 문서가 알림 역할을 해요.**

### handoffs.md와의 역할 분담

| | `handoffs.md` | `maintenance.md` (이 문서) |
|---|---|---|
| 성격 | 파트를 넘길 때의 **인수인계** | 날짜가 되면 다시 열어야 할 **점검 일정** |
| 단위 | 파트 단위 (파트 3 끝 → 파트 4 시작) | 시간 단위 (계속 누적) |
| 담는 것 | 미해결 사항, 집필 기법, 출처 경로, 용어 규약 | 만료일, 재확인 대상 수치, 점검 이력 |

**수치와 일정에 대해서는 이 문서가 단일 출처예요.** 두 문서가 어긋나면 이 문서를 믿고, handoffs 쪽을 고치세요. (파트 2에서 같은 값이 여러 곳에 흩어져 서로 어긋난 적이 있어요.)

## 3. 값을 못 구해 비워둔 것

**수치를 되살리려면 원 출처 확보가 먼저예요.** 그전까지는 지금의 방향성 서술을 유지하세요.

- **동시호가 배분 내부 순서** (1-3, 1-4, 2-6) — 유가증권시장 업무규정 시행세칙 제34조 원문 확보 실패. 세 챕터 모두 "접수 시간의 앞뒤를 따지지 않고 다른 기준으로 나눈다"까지만 서술 중. **어느 챕터에서도 단정하지 마세요.**
- **서킷브레이커 3단계 "1분간 지속" 요건** (2-6) — 1·2단계에만 명시하고 3단계는 뺀 상태. 원문 재확보 후에 추가할 것.
- **배당절차 개선 도입률** (2-3) — klca.or.kr 첨부파일이 JS 다운로드 방식이라 네 번 시도 모두 실패. 웹 검색으로는 분모가 다른 수치들이 나와 확정 불가.

## 4. 출처 접근 경로 (재사용할 것)

시간을 아끼려면 여기부터 보세요. 상세는 `handoffs.md` 4장.

**잘 열리는 곳**
- 법제처 찾기쉬운 생활법령정보 (`easylaw.go.kr`) — 정적 렌더. 세법 확인에 가장 잘 통했어요
- 국세청 안내 페이지 (`nts.go.kr/nts/cm/cntnts/cntntsView.do?...`)
- KRX 규정 원문 (`regulation.krx.co.kr/contents/RGL/03/{코드}/{파일}.jsp`) — 유가증권 03010xxx, 코스닥 03020xxx, 코넥스 03030xxx
- 국가법령정보센터의 **"제정·개정이유" 페이지** (조문 페이지는 JS 렌더라 실패)

**막히는 곳 (다시 시도하지 마세요)**
- 국가법령정보센터 **조문 페이지** — JS 렌더
- `taxlaw.nts.go.kr`의 PDF 다운로드 링크 — WebFetch가 바이너리를 못 읽음
- S&P Dow Jones Indices (`spglobal.com/spdji/...`) — 403 Forbidden
- klca.or.kr 첨부파일 — JS BinDownload 방식

**WebFetch 자체의 한계**: 페이지를 그대로 돌려주지 않고 프롬프트에 맞춰 **요약**해서 줘요. 정확한 숫자를 얻으려면 질문을 최대한 좁히고, **같은 페이지를 두 번 다른 질문으로 조회해 교차 확인**하세요(위 조기폐장 사례처럼 답이 갈릴 수 있어요).

## 5. 점검 절차

한 번 점검할 때 이 순서로 하세요.

1. 위 1장에서 **오늘 날짜를 지난 만료일**이 있는지 본다
2. 있으면 시행 여부를 1차 출처로 확인한다 (**날짜만 보고 바로 고치지 말 것** — 연기가 잦아요)
3. 2장에서 마지막 점검 이후 6개월이 지난 항목을 훑는다
4. 값이 바뀌었으면 해당 챕터의 수치와 **as-of 표기를 함께** 갱신한다
5. 같은 값이 여러 챕터에 있으면 전부 고친다 (위 표의 "있는 곳" 열 참고)
6. `npm run build`와 `npm test`를 돌린다
7. 아래 6장에 점검 이력을 한 줄 남긴다
